# 학생 가이드: 동굴 구조 드론 (rescue_easy)

GPS가 끊기는 동굴로 드론 한 대를 보내 생존자를 찾고, 출발점으로 돌아와 착륙시키는 자율비행 코드를 작성하는 과제입니다. DARPA SubT Challenge의 가상 동굴(`simple_cave_01`)을 그대로 씁니다.

설치와 뷰어 사용법은 [README](../README.md)에 있습니다. 이 문서는 과제의 규칙과 진행 방법을 다룹니다.

## 1. 한 줄 요약

`cavesim.api.Agent`를 상속한 클래스 하나를 `agents/<팀이름>.py`에 작성합니다. 이 에이전트가 `rescue_easy` 코스에서 생존자에게 다가갔다가 기지로 돌아와 착륙하면 성공입니다. 성공한 런은 걸린 시간(랩 타임)으로 비교합니다.

## 2. 임무 규칙

| 항목 | 값 |
|---|---|
| 맵 | `rescue_easy` (DARPA SubT `simple_cave_01`) |
| 드론 수 | 1대 (`--drones 1`) |
| 출발 | 동굴 밖 기지 `(0, 0, 1.5)`. 동굴 입구는 동쪽 약 14 m |
| 생존자 | 직선거리 약 280 m. 실제 비행 경로는 이보다 깁니다 |
| 구조 | 실제 생존자에서 3 m 안에 들어가고, 생존자가 가려지지 않은 채 보여야 합니다 |
| 귀환 | 구조한 뒤 기지에서 수평 3 m 안에 **착륙**해야 합니다. 착륙하면 다시 뜰 수 없습니다 |
| 랩 타임 | 출발부터 귀환 착륙까지의 시간. 점수이며 짧을수록 좋습니다 |
| 제한 | 임무 시간 1200 s, 배터리 1200 s(제자리 비행 기준. 빨리 날면 더 빨리 닳습니다) |
| 실패 | 시간 초과, 배터리 소진, 추락(2 m/s 넘게 충돌하거나 75° 넘게 기울어짐), 코스 이탈 |

코스 이탈: 동굴 밖 대기 구역(`info["staging_box"]`)을 벗어났는데 위아래에 바위가 없는 상태가 1초 이어지면 이탈입니다. 동굴 위로 넘어가거나 지형 아래로 빠지는 것을 막는 규칙입니다.

### 에이전트가 처음에 받는 정보 (`info`)

| 키 | 뜻 |
|---|---|
| `info["target"]` | 생존자 좌표 (오도메트리 좌표계). 오차가 있을 수 있습니다 |
| `info["target_error_m"]` | 위 좌표의 최대 오차, m |
| `info["entrance"]`, `info["entrance_route"]` | 동굴 입구 위치와, 기지에서 입구까지의 직선 구간 |
| `info["staging_box"]` | 동굴 밖 대기 구역 `[[xmin,ymin,zmin],[xmax,ymax,zmax]]` |
| `info["base"]`, `info["home_radius"]` | 기지 위치, 귀환 인정 반경(3 m) |
| `info["max_speed_xy"]`, `info["max_speed_z"]` | 속도 한계 3 m/s, 1.5 m/s |

지도는 주지 않습니다. 동굴 모양은 LiDAR로 직접 알아내야 합니다. 매 틱(10 Hz) 받는 값(`Observation`)과 보내는 명령(`Command`)은 모두 [`cavesim/api.py`](../cavesim/api.py)에 정의돼 있습니다. 센서 사양은 README 3장과 [센서 문서](sensors.md)에 있습니다.

동굴 밖에서는 `obs.gps`가 들어오고, 동굴 안에서는 `None`입니다. 동굴 안에서는 `obs.pos`(LiDAR-관성 오도메트리 추정값)에 의지해야 하며, 이 값은 비행할수록 조금씩 틀어집니다.

## 3. 실행

```
:: 뷰어로 보기 (표준 조건)
python -m cavesim.run --agent agents.team1 --map rescue_easy --drones 1 --lidar lite

:: 화면 없이 결과만
python -m cavesim.run --agent agents.team1 --map rescue_easy --drones 1 --lidar lite --headless

:: 생존자 좌표에 20 m 오차 (도전 조건)
python -m cavesim.run --agent agents.team1 --map rescue_easy --drones 1 --lidar lite --target-error 20
```

결과의 `"success": true`와 `"lap_time_s"`를 보세요. 실패했다면 `crashed`, `crash_cause`, `battery_dead`, `out_of_course`, `rescued_at_s`(구조는 했는지)가 원인을 알려 줍니다.

뷰어 아래쪽 막대는 리플레이입니다. 슬라이더를 끌어 지난 장면을 다시 보고, 재생 속도(1×/4×/16×)를 고를 수 있습니다. 새로고침해도 기록은 남아 있습니다.

### 여러 시드로 평가하기

시드를 바꾸면 센서 잡음과 공기 교란, 생존자 좌표 오차의 방향이 바뀝니다. 한 시드에서 성공해도 다른 시드에서 실패할 수 있으니, 항상 여러 시드로 확인하세요.

```python
# eval.py: 시드 0~9 평가
from cavesim.config import SimConfig
from cavesim.sim import run_mission
from agents.team1 import Agent

for seed in range(10):
    r = run_mission("maps/rescue_easy", Agent, n_drones=1, lidar="lite", seed=seed,
                    cfg=SimConfig(target_error_m=0.0))      # 도전 조건은 20.0
    print(seed, r["success"], r["lap_time_s"], r["crashed"], r["battery_dead"], r["out_of_course"])
```

화면 없이 돌려도 한 런에 시간이 걸립니다(참조 에이전트 실측: 비행 373 s짜리 런 하나에 약 15분. 내 에이전트가 가벼우면 더 빠릅니다). 시드를 여러 명령 창에 나눠 동시에 돌리면 빠릅니다.

## 4. 단계별 진행 (권장)

각 단계마다 **확인 기준**을 통과한 뒤 다음으로 넘어가세요.

| 단계 | 할 일 | 확인 기준 |
|---|---|---|
| 1. 이륙과 입구 | GPS(`obs.gps`)로 `entrance_route`를 따라 입구까지 비행 | 10개 시드 모두 입구에 도착, 충돌 0 |
| 2. 지도 | LiDAR 점을 `body_to_odom`으로 옮겨 3D 격자 지도(점유 격자)에 쌓기. `debug()`로 뷰어에 그려 보기 | 뷰어의 동굴 벽과 내 지도가 겹쳐 보임 |
| 3. 안전 비행 | 벽과 거리를 두고 속도를 제한하는 장애물 회피 | 입구에서 50 m 들어가는 동안 충돌 0 |
| 4. 목표까지 | 지도 위 경로 탐색(A* 등)과 미지 영역 탐사(프런티어)로 `target`까지 가기 | 구조 성공(`rescued_at_s`에 기록) |
| 5. 귀환과 착륙 | 지나온 길(breadcrumb)이나 지도로 기지까지 돌아와 착륙 | `success: true` |
| 6. 견고성 | 시드 10개, 이후 `--target-error 20` | 성공률과 랩 타임 개선 |

5단계까지가 기본 과제이고, 6단계의 `--target-error 20`은 도전 과제입니다. 오차가 있으면 주어진 좌표에 가도 생존자가 없을 수 있으므로, 생존자 탐지기(`obs.detections`)로 주변을 찾아야 합니다.

## 5. 먼저 알아 두면 좋은 함정

참조 에이전트를 만들면서 실제로 겪은 문제들입니다.

- **LiDAR 사각지대.** LiDAR는 기체 아래에 달려 있어서 위쪽 약 33° 이상은 프로펠러에 가려 보지 못합니다. 바로 위와 바로 아래의 원뿔 영역도 비어 있습니다. 위로 올라갈 때는 보이지 않는 천장에 닿을 수 있습니다.
- **천장 효과.** 천장에서 0.8 m 안으로 들어가면 최대 중력의 35%로 천장 쪽에 빨려 붙습니다. 약한 하강 명령으로는 빠져나오지 못합니다. 명령한 방향으로 움직이지 않으면 막힌 것으로 보고 지도에 기록하세요.
- **로터 먼지.** 바닥 1 m 안에서는 먼지가 가짜 LiDAR 점을 만듭니다. 한 번 찍힌 점을 무조건 바위로 확정하면 통로가 지도에서 막힙니다. 여러 번 관측해서 확률로 쌓으세요(log-odds).
- **오도메트리 오차.** `obs.pos`는 1 km에 수 m까지 틀어집니다. 돌아올 때 같은 곳을 지나면 지도가 어긋나 보일 수 있습니다. 귀환 착륙 지점은 동굴 밖에서 다시 잡히는 GPS로 맞추면 됩니다.
- **벽 근처 공기.** 벽에서 1.2 m 안에서는 난류가 커집니다. 좁은 곳에서는 속도를 줄이세요.
- **목표 좌표만 보고 직진하지 마세요.** 직선으로 가까운 쪽이 막다른 길일 때가 많습니다. 지도에서 실제로 열린 길을 따라가야 합니다.

## 6. 해서는 안 되는 것

에이전트는 `__init__`의 `info`와 매 틱의 `obs`만 써야 합니다.

- `maps/` 아래 파일(`truth.json`, `mesh.npz`, `flyable_*.npz`, `map.json`의 `graph`)을 읽지 마세요. 정답 위치와 동굴 모양, 경로 골격이 들어 있습니다.
- `cavesim/` 시뮬레이터 내부(실제 위치, PyBullet 객체)에 접근하거나 수정하지 마세요.
- 다른 팀이나 `agents/planner.py`(참조 에이전트)의 코드를 복사하지 마세요. 읽고 아이디어를 얻는 것은 됩니다. 가져온 아이디어는 보고서에 출처를 밝히세요.

채점할 때는 코드를 검사합니다. 교수자의 시뮬레이터와 숨긴 시드로 다시 실행합니다.

## 8. 제출물과 평가 (교수자가 조정)

**제출물**
1. `agents/<팀이름>.py` (필요하면 같은 이름으로 시작하는 보조 파일)
2. 보고서: 설계(지도, 경로, 비행 제어, 귀환), 실패 사례 분석, 시드별 결과표
3. 시연 영상: 뷰어 화면 녹화 1개

**평가 예시**
| 항목 | 비중 | 기준 |
|---|---|---|
| 기본 성공 | 40% | 숨긴 시드 10개에서 오차 0 성공률 |
| 랩 타임 | 15% | 성공한 런의 중앙값, 팀 간 순위 |
| 도전 과제 | 15% | `--target-error 20` 성공률 |
| 보고서 | 25% | 실패 원인을 기록(로그, 리플레이)으로 보였는가 |
| 코드 | 5% | 읽을 수 있는가 |

## 9. 막혔을 때

- 뷰어에서 `에이전트 디버그`를 켜고, `debug()`로 경로·목표점·모드를 보내 화면에서 확인하세요.
- 실패한 시드는 `--seed N`으로 똑같이 다시 재현됩니다. 같은 코드와 시드면 결과도 같습니다.
- 성공한 런도 리플레이로 확인하세요. 벽에 긁히며 겨우 성공한 런은 다른 시드에서 실패합니다.
